# From Pinterest — Next.js store

متجر Next.js + TypeScript، بنفس التصميم الكريمي والأخضر والبينك واللوجو الشفاف. اللغة الافتراضية English؛ يمكن التبديل للعربي مع RTL وحفظ الاختيار. المنتجات الحالية أمثلة قابلة للتعديل.

## التشغيل

استخدم Node.js **24 أو أحدث** لأن قاعدة البيانات تستخدم `node:sqlite` المدمجة، بدون خدمة خارجية.

```bash
npm install
cp .env.example .env.local
```

افتح `.env.local` وضع كلمة مرور قوية خاصة بك في `ADMIN_PASSWORD`، ثم:

```bash
npm run dev
```

المتجر: http://localhost:3000 — الإدارة: http://localhost:3000/admin

```bash
npm run typecheck
npm run build
npm start
```

## تعديل المنتجات بدون تعديل الكود

1. افتح `/admin` وسجّل بكلمة المرور التي وضعتها.
2. اختار منتجًا أو New product.
3. عدّل الاسم والوصف بالعربي والإنجليزي والسعر والمخزون والقسم والأجواء.
4. أضف صورتك إلى `public/products` واكتب مسارها مثل `/products/my-basket.jpg` في Image path، ثم Save product.
5. حدّث صفحة المتجر لرؤية التعديل. لوقف بيع منتج اجعل مخزونه صفرًا.

لا يوجد رفع صور من المتصفح في هذه النسخة؛ الصور ملفات داخل المشروع. المنتجات تظهر في أقسامها تلقائيًا، والهوم يعرض أول ثلاث قطع بكل قسم. إدارة الأقسام والأجواء من `src/lib/catalog.ts`.

## الباك إند والداتا

- SQLite تحفظ المنتجات والطلبات فعليًا في `data/store.sqlite` وتبقى بعد إعادة التشغيل.
- الداتا الأولية في `src/lib/seed.ts` وتُنسخ مرة واحدة فقط عند إنشاء القاعدة؛ بعد ذلك التعديل من الإدارة.
- `GET /api/products`: الكتالوج العام بدون بيانات العملاء.
- `POST /api/orders`: يتحقق من بيانات العميل والمخزون ويحسب السعر من قاعدة البيانات ويحفظ الطلب ويخصم المخزون في transaction واحدة؛ أي خطأ يلغي العملية كلها.
- `/api/admin/products`: قراءة وتعديل المنتجات بكلمة مرور.
- `/api/admin/orders`: آخر 200 طلب مع التفاصيل؛ تظهر في صفحة الإدارة.
- كلمة المرور في متغير بيئة على السيرفر؛ لا تحفظ في localStorage. أعد الدخول بعد تحديث صفحة الإدارة.
- السلة محفوظة في متصفح العميل، وعدادها يمثل عدد القطع.

## تنظيم الكود

```text
src/
  app/                     صفحات ومسارات Next.js
    api/products/          قراءة الكتالوج
    api/orders/            إنشاء الطلب
    api/admin/             إدارة المنتجات والطلبات
    admin/                 صفحة الإدارة
    shop/, products/       المتجر وتفاصيل المنتج
    cart/, checkout/       السلة وإتمام الطلب
  components/              كمبوننتس العرض القابلة لإعادة الاستخدام
    Header, Footer, Logo
    ProductCard            بطاقة منتج مشتركة
    SectionHeading         عنوان سكشن مشترك
    StoreProvider          اللغة والسلة والكتالوج القادم من السيرفر
    admin/ProductForm      فورم منتج مشترك للإضافة والتعديل
    admin/AdminPage        شاشة الإدارة
  lib/
    catalog.ts             أنواع البيانات والأقسام والأجواء
    seed.ts                بيانات أولية تجريبية
    database.ts            اتصال SQLite وإنشاء الجداول
    products.ts            قراءة وحفظ المنتجات
    admin.ts               التحقق من كلمة مرور الإدارة
public/products/           صور المنتجات
```

كل ملف في `app` يستدعي كمبوننت الصفحة. العرض منفصل عن قاعدة البيانات، وكل واجهات المنتجات تستخدم نفس الكتالوج القادم من السيرفر. ألوان الهوية في `src/app/globals.css` واللوجو في `public/logo-transparent.png`.

## قبل النشر التجاري

هذه نسخة تشغيل محلي بباك إند حقيقي، وليست منشورة. تحتاج استضافة Node.js بمجلد دائم للـSQLite؛ لا تعتمد على قرص مؤقت في serverless مثل Vercel. على استضافة serverless استبدل طبقة `lib/database.ts` و`lib/products.ts` بقاعدة بيانات خارجية. استخدم HTTPS عند النشر، ونسخًا احتياطية للقاعدة. لا تنشر ملف البيئة أو قاعدة بيانات العملاء ضمن Git.

الدفع الإلكتروني غير مربوط، وتكلفة التوصيل يتم تأكيدها يدويًا؛ الإجمالي المعروض للمنتجات فقط. الطلبات المحفوظة تحتاج متابعة من الإدارة؛ لا يوجد إرسال إيميل أو واتساب تلقائي. يجب تأكيد وسائل التواصل والسياسات الفعلية واستبدال الصور التجريبية قبل استقبال العملاء. الإدارة البسيطة الحالية تستخدم كلمة مرور واحدة؛ قبل الإطلاق العام أضف تسجيل دخول كامل وحماية من المحاولات المتكررة وحدودًا لإنشاء الطلبات. لا توجد إدارة حالات الطلب/إلغاء واسترجاع مخزون في الواجهة بعد.
